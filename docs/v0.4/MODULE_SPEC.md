# MaìLang 模块规范

> **项目链接**：[GitHub](https://github.com/Maicarons/mailang) · [模块加载器源码](https://github.com/Maicarons/mailang/tree/master/crates/mailang-module) · [libs 目录](https://github.com/Maicarons/mailang/tree/master/libs)

## 目录结构

每个模块必须遵循以下目录结构：

```
libs/<module_name>/
├── README          # 模块说明文档（无扩展名）
├── mailib.ini      # 模块配置文件
├── lib.mai         # 模块入口文件
├── example/        # 示例代码目录
│   └── basic.mai   # 基础使用示例
└── test/           # 测试代码目录
    └── test_<module>.mai  # 模块测试
```

## mailib.ini 格式

```ini
[module]
name = <模块名>
version = <版本号，语义化版本>
description = <简短描述>
author = <作者>
entry = lib.mai
```

示例：
```ini
[module]
name = time
version = 0.2.0
description = Time and date functions
author = MaìLang Team
entry = lib.mai
```

## README 格式

README 文件无扩展名，内容格式如下：

```
# <模块名> - <简短描述>

版本: <版本号>

## 功能说明

<模块功能的详细说明>

## API 列表

### <函数名>(<参数>)

<函数描述>

- 参数: <参数说明>
- 返回值: <返回值说明>

## 使用示例

​```mai
import "<模块名>"
// 示例代码
​```
```

## 模块导入方式

解析顺序（命名导入）：

1. 项目根目录 `mailang.toml` 中的 `[dependencies]` 显式依赖
2. 本地 `libs/`（`mailang-cli` 同目录或 `base_dir/libs`、`CWD/libs`）
3. 相对路径导入（`./`、`../`）

### 方式一：命名导入（推荐，仅 PC）

```mai
import "time"
let ts = time.now()
```

模块文件需放在 `mailang-cli.exe` 同目录的 `libs/` 下，或通过 `mailang.toml` 声明。

### 方式二：路径导入（全平台）

```mai
import "./libs/time"
let ts = time.now()
```

支持相对路径和绝对路径。

### 方式三：项目依赖（mailang.toml）

项目根目录可放置 `mailang.toml`，用 `[dependencies]` 将模块名映射到本地路径、GitHub 仓库或 git URL：

```toml
[package]
name = "my-app"
version = "0.1.0"

[dependencies]
# 简写：相对项目根的模块目录 / 文件
json = "libs/json"
utils = "./local/utils"
sensors = "../shared/sensors"
# 表形式：本地路径
io_utils = { path = "./local/io_utils" }
# 表形式：GitHub（离线解析，见下文；网络拉取由宿主/CI 负责）
cool = { github = "org/repo" }
# 表形式：任意 git URL
other = { git = "https://example.com/org/repo.git" }
```

- **键**（`=` 左侧）是导入时使用的模块名，例如 `import "json"`。
- **path** 值是相对项目根的路径；也支持绝对路径。路径可以是模块目录（读取 `mailib.ini` 的 `entry`，默认 `lib.mai`）或直接的 `.mai` 文件。
- **github = "org/repo"** / **git = "`<url>`"** 为远程依赖声明。`mailang` **不发起网络请求**（无 HTTP 客户端依赖）；解析阶段只做离线查找，拉取由宿主 / CI 完成（例如 `curl` / `git clone`）。

#### 远程依赖离线解析顺序

对 `github` / `git` 依赖，按模块名 `name` 依次查找：

1. 项目内 `vendor/`<name>`/`
2. 用户缓存 `~/.mailang/pkg/`<name>`/`（Windows: `%USERPROFILE%\.mailang\pkg\`<name>`\`）
3. （未命中则视为未解析；网络 fetch 是 host-op）

命中目录后，按普通模块规则读取 `mailib.ini` 的 `entry`（默认 `lib.mai`）。

`path` 依赖不走 vendor，只按路径解析。

#### 规划安装：`mailang add`（仅写计划，不拉取）

```bash
mailang add json=libs/json          # path
mailang add ./local/utils           # path（名字取末段）
mailang add cool=github:org/repo    # github
mailang add github:org/repo         # github（名字取 repo）
mailang add org/repo                # mip 风格 github
mailang add foo=git:https://example.com/x.git
mailang add git:https://example.com/x.git
```

`mailang add` 只把依赖**写入** `mailang.toml`（github/git 会附注释标明 fetch 为 host-op），不会访问网络。把检出结果放进 `vendor/`<name>`/` 或 `~/.mailang/pkg/`<name>`/` 后即可离线解析。

查看已解析依赖：

```bash
mailang deps
# 或指定项目根
mailang deps --path /path/to/project
# 打印 / 校验 mailang.lock（过期或哈希不一致时退出码 1）
mailang deps --lock
```

输出列：名称、`mailib.ini` 中的版本（无则为 `-`）、内容哈希、解析后的路径。若找不到 `mailang.toml`，会提示如何创建。

解析 API 见 `crates/mailang-module/src/deps.rs`（`parse_manifest` / `resolve_dependencies` / `dependency_map` / `plan_add`）。

## mailang.lock（SEMVER-lite + 内容哈希）

解析 `[dependencies]` 时会在项目根写入 / 复用 `mailang.lock`：

- **已有且匹配** → 复用（不重写）
- **缺失或不匹配** → 刷新重写

### 格式

纯文本、`|` 分隔、一行一条；`#` 为注释；`-` 表示空字段：

```
# mailang.lock -- generated by mailang; do not edit by hand.
# SEMVER-lite + content hash of the module entry file.
# fields: name | version | path | hash
cool | 1.0.0 | vendor/cool | 6f8a2c1b0d3e4f50
json | 0.2.0 | libs/json | a1b2c3d4e5f60718
```

| 字段 | 含义 |
|------|------|
| `name` | 依赖名（`mailang.toml` 键） |
| `version` | `mailib.ini` 的 `version`（SEMVER-lite，如 `0.2.0`；可缺省 minor/patch） |
| `path` | 解析后的入口路径（尽量相对项目根，`/` 分隔） |
| `hash` | 入口文件（`lib.mai` 或 `mailib.ini` `entry`）字节的 FNV-1a 64 内容哈希（16 位十六进制） |

### SEMVER-lite

- 解析：`MAJOR[.MINOR[.PATCH]]`，缺省段视为 `0`（`1.2` ≡ `1.2.0`）。
- 锁匹配按 SEMVER-lite 相等（不强制字面量一致）；比较 `semver_lite_cmp` 提供 `-1/0/1` 排序。
- 锁记录的是**已解析到的具体版本**，不是约束表达式。

### 校验

`mailang deps --lock` 对比锁文件与当前解析结果，逐条状态：

- `ok` / `planned`（远程依赖已记入锁但尚未拉取，字段一致）
- `version-mismatch` / `path-mismatch` / `hash-mismatch`
- `missing-in-lock` / `extra-in-lock` / `missing-on-disk`

全部为 `ok` 或 `planned` 且锁文件存在 → 退出码 `0`；否则打印 `STALE` 并退出码 `1`（随后运行 `mailang deps` 可刷新锁）。

API：`read_lockfile` / `write_lockfile` / `ensure_lock` / `verify_lock` / `content_hash`。

## 包注册表（Registry）

MaìLang 提供 **文件系统优先、可静态托管** 的小型注册表（crates.io 风格）。
实现见 `crates/mailang-module/src/registry.rs`；CLI 见 `mailang publish/install/search/yank/registry`。
完整使用指南：[docs/guide/registry.md](./guide/registry.md)。

### 目录布局

```
<registry-root>/
├── registry.toml                 # 元数据（format = 1）
├── index/
│   └── <name-prefix>/<name>      # JSON Lines 索引（每行一个版本）
└── pkgs/
    └── <name>/
        ├── <vers>/               # 包目录拷贝（mailang.toml + lib.mai + mailib.ini + README）
        └── <name>-<vers>.mpkg    # 长度前缀打包（HTTP 单文件拉取）
```

**name-prefix**（crates.io 风格）：

| 名称长度 | 路径 |
|---------|------|
| 1 | `index/1/<name>` |
| 2 | `index/2/<name>` |
| 3 | `index/3/<首字符>/<name>` |
| ≥4 | `index/<前两字符>/<name>` |

### 索引条目（JSON Lines）

`index/`<name-prefix>`/<name>` 每行一个 JSON 对象：

```json
{"name":"json","vers":"0.2.0","deps":["utils"],"cksum":"a1b2c3d4e5f60718","yanked":false,"description":"JSON helpers"}
```

| 字段 | 含义 |
|------|------|
| `name` | 包名 |
| `vers` | SEMVER-lite 版本 |
| `deps` | 依赖名列表（发布时从 `mailang.toml` `[dependencies]` 收集） |
| `cksum` | `.mpkg` 字节的 FNV-1a 64 内容哈希（16 位十六进制） |
| `yanked` | 是否撤回（install 默认拒绝） |
| `description` | 简短描述（用于 search） |

### `.mpkg` 打包格式

无 zip 依赖的简单容器：

```
magic "MAILANGPKG1"
u32 LE entry_count
per entry:
  u32 LE name_len | name bytes
  u64 LE data_len | data bytes
```

文件系统注册表同时写 `pkgs/`<name>`/`<vers>`/` 目录拷贝（可调试）与 `.mpkg`；HTTP 安装走 `.mpkg` 并校验 `cksum`。

### 默认注册表位置

优先级：

1. 环境变量 `MAILANG_REGISTRY`（路径或 `http(s)://` 基址）
2. `./.mailang-registry`
3. `~/.mailang/registry`（Windows: `%USERPROFILE%\.mailang\registry\`）

### CLI

```bash
mailang registry init <path>              # 创建空注册表骨架
mailang publish [--registry <path>] [--allow-republish]
mailang install <name>[@<ver>] [--registry <path>] [--global] [--allow-yanked] [--no-manifest]
mailang search <query> [--registry <path>]
mailang yank <name> <vers> [--registry <path>] [--undo]
```

- **publish**：打包当前项目（`mailang.toml` + `lib.mai` 等），版本已存在则拒绝（除非 `--allow-republish`），写入 `pkgs/` 并追加索引。
- **install**：解析索引（裸名取最新非 yanked，或精确 `@ver`），拷贝到 `vendor/`<name>`/`（或 `--global` 到 `~/.mailang/pkg/`<name>`/`），并改写 `mailang.toml` 的 path 依赖。
- **search**：在 `index/**` 中按名称/描述子串搜索（仅文件系统注册表）。
- **yank**：将版本标记 `yanked: true`；`--undo` 恢复。

### HTTP 注册表

注册表目录可直接用静态服务器托管。`--registry https://…` 时：

- **install / 读索引**：通过 `curl -fsSL` 拉取 `index/...` 与 `pkgs/.../*.mpkg`（无 HTTP crate）。
- **publish / yank / search / init**：需要文件系统路径（HTTP 只读）。

## 函数命名规范

- 使用 snake_case 命名函数
- 函数名应简洁明了
- 避免使用缩写（除非是通用缩写如 `str`, `num`）

## 模块间依赖

- 模块可以相互引用，但不能交叉引用（A 引用 B，B 引用 A）
- 依赖关系应为有向无环图（DAG）

## 内置函数

模块可以调用以下内置函数：

- `time_now()` - 获取当前时间戳（毫秒）
- `time_now_secs()` - 获取当前时间戳（秒）
- `time_date()` - 获取当前日期字符串
- `time_datetime()` - 获取当前日期时间字符串
- `time_year()` - 获取当前年份
- `time_month()` - 获取当前月份
- `time_day()` - 获取当前日期
- `time_hour()` - 获取当前小时
- `time_minute()` - 获取当前分钟
- `time_second()` - 获取当前秒数
- `time_sleep(ms)` - 休眠指定毫秒
- `time_elapsed(start)` - 计算经过的时间
